# План: получить настоящий .apk, который каждый ставит сам

Требование: приложение уже должно быть открыто и работать по
постоянной ссылке (см. ПРОЧТИТЕ_СНАЧАЛА.md, шаг 1) — например
`https://ВАШ_НИК.github.io/pauza-app/`. Без этого APK собрать нельзя,
так как .apk — это, по сути, «обёртка» вокруг вашего сайта плюс
кэш для офлайн-режима: сначала должен существовать сам сайт.

Инструмент — **pwabuilder.com**, официальный сервис Microsoft для
превращения PWA в Android/iOS/Windows-пакеты. Полностью в браузере,
без Android Studio, без установки чего-либо на компьютер.

---

## Шаг 1. Проверка PWA

1. Откройте https://www.pwabuilder.com
2. В поле вставьте вашу ссылку `https://ВАШ_НИК.github.io/pauza-app/`
   и нажмите **Start**.
3. Сервис проверит manifest.json, service worker и иконки — покажет
   баллы (Manifest / Service Worker / Security). У нас всё уже
   подготовлено, так что баллы должны быть зелёными или почти
   зелёными. Если где-то жёлтый — не страшно, для базового APK
   это не критично.

## Шаг 2. Сборка пакета

1. Нажмите **Package For Stores**.
2. Выберите платформу **Android**.
3. Откроется форма настроек — большинство полей можно оставить
   по умолчанию (сервис берёт их из manifest.json). Проверьте:
   - **Package ID**: например `com.pauza.app` (это внутреннее имя
     приложения, потом его не поменять — выберите сразу осмысленное)
   - **App name**: Пауза
   - **Signing key**: выберите **Generate new signing key** —
     сервис создаст ключ подписи автоматически и отдаст вам файл
     `signing.keystore` — **сохраните его в надёжном месте**, он
     понадобится, если решите позже обновлять приложение через
     этот же Package ID.
4. Нажмите **Generate**.
5. Через 1–2 минуты скачается .zip с несколькими файлами внутри,
   среди них — `app-release-signed.apk` (или `.aab` для Google Play).
   Это и есть готовый APK.

## Шаг 3. Digital Asset Links (чтобы приложение открывалось без строки браузера сверху)

Без этого шага APK будет работать, но при запуске может на секунду
показывать тонкую полоску браузера сверху. Чтобы её убрать:

1. В скачанном .zip из шага 2 найдите файл `assetlinks.json`
   (PWABuilder генерирует его вместе с APK).
2. Создайте в вашем репозитории на GitHub (из ПРОЧТИТЕ_СНАЧАЛА.md)
   папку `.well-known` и положите туда этот `assetlinks.json`.
   Итоговый путь должен открываться по адресу:
   `https://ВАШ_НИК.github.io/pauza-app/.well-known/assetlinks.json`
3. Проверьте в браузере, что этот адрес отдаёт JSON, а не 404.
4. Если раньше уже собрали APK без этого файла — пересобирать не
   обязательно, полоска браузера — это только косметика, само
   приложение и дневник работают одинаково.

## Шаг 4. Раздача файла друзьям

Теперь у вас есть один файл `app-release-signed.apk` (обычно
15–25 МБ). Его можно:

- отправить в Telegram/WhatsApp напрямую как файл;
- залить на Google Drive / Яндекс.Диск и скинуть ссылку;
- передать через USB.

### Что делать получателю (один раз в жизни телефона):

1. Скачать файл.
2. При открытии Android покажет предупреждение
   «Установка запрещена» — это нормально для файлов не из Google
   Play. Нажать **Настройки** в этом же диалоге.
3. Включить переключатель **Разрешить из этого источника**
   (формулировка отличается на разных Android — «Установка из
   неизвестных источников» / «Unknown apps»).
4. Вернуться назад и нажать **Установить**.
5. Готово — иконка появится в списке приложений, как у любого
   обычного приложения из Google Play.

Это разрешение дают один раз для конкретного приложения-источника
(например, для Telegram) — при следующей установке через Telegram
экран с настройками уже не появится.

## Важно понимать про этот способ APK

Собранный так APK — это «Trusted Web Activity»: контейнер, который
при первом запуске подгружает ваш сайт с GitHub Pages, а дальше
пользуется тем же офлайн-кэшем (service worker), что и в браузере.
Это значит:
- сайт на GitHub Pages должен оставаться существующим и дальше —
  если вы его удалите, у всех, кто уже поставил APK, приложение
  перестанет обновляться (но уже загруженная офлайн-копия какое-то
  время продолжит работать);
- обновить контент (например, добавить новые дни или поправить
  текст) можно, просто заменив файлы в репозитории на GitHub — не
  нужно пересобирать и заново раздавать APK, все получат обновление
  автоматически при следующем подключении к интернету.

Если в будущем захотите публикацию в Google Play официально — тот
же .zip из шага 2 содержит файл `.aab` (Android App Bundle), именно
его требует Google Play Console при загрузке.
